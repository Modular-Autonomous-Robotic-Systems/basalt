# SLAM analysis and visualisation dashboard

Reads one or more Basalt run directories under `--logdir` (each holding `config.json`, `calibration.json` and the `Logger`/`AggregateStats` CSVs) and serves an interactive, lazily loaded comparison dashboard with cross-tab linked zoom. **Correction, 2026-10-22.** This was a single static `dashboard.html` file at first, then briefly a static shell that lazily loaded each tab's own self-contained `tabs/<tab>.html` into an iframe, trading away cross-tab zoom linking to get there. It is now a live `panel serve` app instead, `plans/dashboard_live_migration.md`, which gets both properties at once, Bokeh's own linked panning (one `Range1d` shared across every `t_ns` based figure, including figures on other tabs) plus `pn.Tabs(dynamic=True)` genuinely deferring a tab's content until it is first opened, something neither achieves against a file with no server left once it's saved. The cost accepted for this is the one in the next section.

## Running it

Inside `analysis_container` (built and spawned by `djinn init docker analysis` / `djinn up analysis [gpus]`), the recommended path is

```
./djinn start slam-analysis /ws/logs/<stamp>
```

which is equivalent to running

```
python3 -m panel serve scripts/analysis/dashboard.py --port 5006 --address 0.0.0.0 --allow-websocket-origin="*" --args --logdir /ws/logs/<stamp>
```

and opening `http://localhost:5006` (`analysis_container` runs with `--net=host`, `docker/scripts/start.sh`, so no port mapping is needed). This blocks the terminal for as long as the dashboard is open, Ctrl+C stops it, the same as any other long running `djinn start` entry. `--config` defaults to `scripts/analysis/config.json` alongside the script; pass a different file via `--args --logdir ... --config ...` to change which plots and metrics run without editing the shipped default. Unlike before, there is no file to copy or email elsewhere, viewing the dashboard means a `panel serve` process is running somewhere reachable. `--workers <N>` (also via `--args`) controls how many experiments are processed concurrently, both `class DataReader`'s own CSV loading (a thread pool, since pandas releases the GIL during the actual parse) and the trajectory/excitation-covariance/BoW-PR-curve tabs' per-experiment compute (a process pool, needed for genuine multi-core use on the Python-level loops in `metrics.excitation_covariance`/`metrics.bow_pr_curve`); it defaults to `min(experiments, os.cpu_count())` and `--workers 1` reproduces the original fully sequential behaviour exactly. On `analysis_container` started with `--gpus` (`cupy` importable), a value above `1` means every pooled worker process independently acquires its own CUDA context for the trajectory tab's RPE sweep, which can contend for a single GPU, `plans/analysis_module.md` section 18.

## Output

Inside `--logdir`,

```
metrics.csv           one row per metric, one column per experiment
figures/<tab>/*.html  every plot, individually reopenable, offline, no server needed
```

No `dashboard.html` is written, the dashboard itself is the live page `panel serve` serves, not a file under `--logdir`. Its first tab, `scalars`, is every scalar quantity this run computed, filterable and sortable, the same table `metrics.csv` holds, built eagerly since a table is cheap. No scalar is ever drawn as a standalone tile shaped figure inside a subsystem tab, every one of them lives in this one table instead. `metrics.csv`'s first three columns are `category` (the tab a metric belongs to), `name` (a phrase, "ATE (m)") and `type` (the statistic kind, "rmse"/"mean"/"std"/"percentile"/"rate"/"value"); every other column is one experiment's own value. Every other tab is wrapped in `pn.param.ParamFunction(fn, lazy=True)`, Panel's own documented pattern for `pn.Tabs(dynamic=True)`, so a tab's figures are only attached to the live page the first time that tab is selected, `class Analysis.run()` itself still builds every tab's figures and writes every `figures/<tab>/*.html` eagerly regardless, so `metrics.csv` and `figures/` are exactly as complete as they were before this change, only the browser-side attach step is deferred. Every file under `figures/` embeds its own JavaScript (`include_plotlyjs=True` for Plotly figures, `resources=INLINE` for the Bokeh ones below), so any one of them opens standalone with no internet reachable and no `panel serve` process running.

Every experiment is its own simulation run on its own wall clock, so `DataReader` offsets every one of its logs by that experiment's own mission start before any plot sees them (`class DataReader._scan_epochs`, the minimum `t_ns` across every CSV in that experiment's directory), making two experiments' time series comparable on mission relative time rather than on whatever absolute moment each was launched. Every time series plot draws markers only, never a connected line, because neither two experiments nor two logging sites within one experiment share a sampling grid, and a line drawn between two available samples would read as continuous data across whatever gap, a dropped frame among them, actually separates them. `time_series`/`multi_axis_time_series`/`categorical_timeline`, the three shapes ever plotted against `t_ns`, render as native Bokeh figures with `output_backend="webgl"` rather than Plotly, so a mission running to several thousand frames still draws to one WebGL canvas per series regardless of point count; every other shape stays a plain `plotly.graph_objects.Figure` rendered via `go.Scattergl`/`go.Scatter` as before, `visualisation.py` never needed cross-figure linking on those and still doesn't.

Every plot is centred on the page. Every one of the three `t_ns` based shapes above shares one `bokeh.models.Range1d` (`class Analysis.shared_t_range`, created once per browser session), zooming into a time window on any one of them, in any tab, zooms every other one sharing it to the same window, Bokeh's own linked panning, no hand written JavaScript. Plots whose x axis is not `t_ns`, a global solver iteration index among them (`cost_curve`/`damping_trace`/`cost_split`/`mapper_cost_curve`/`mapper_damping_accept_reject`), are not linked, since their axis carries no time meaning a `t_ns` window could be compared against; each still gets Bokeh's own independent, unshared range.

## Files

| File | Contents |
|---|---|
| `dashboard.py` | `--logdir`/`--config` parsed from `sys.argv` (`panel serve ... --args`), constructs `DataReader` and `Analysis`, calls `Analysis.run()` eagerly, serves the tabs and metrics table as a live `panel serve` app via `.servable()`, module level code rather than behind `if __name__ == "__main__":` since the Bokeh/Panel server model re-executes the whole script per browser session |
| `analysis.py` | `class Analysis`, one `_analyse_<tab>` method per tab, reads `config.json`, writes `metrics.csv` and `figures/`, owns the one `Range1d` shared across every linked figure |
| `data_reader.py` | `class DataReader`, loads one CSV across every experiment at a time |
| `trajectory_analysis.py` | `class TrajectoryAnalysis`, ATE/RPE, wraps `class Alignment` |
| `alignment.py` | `class Alignment`, the three Umeyama alignment modes |
| `metrics.py` | stateless scalar/DataFrame producing functions |
| `visualisation.py` | stateless Figure producing functions, Bokeh for `time_series`/`multi_axis_time_series`/`categorical_timeline`, Plotly for every other shape |
| `config.json` | every plot/metric's `enabled` flag and hyperparameters |

## `config.json`

One top level key per tab (`trajectory`, `optical_flow_detection`, `optical_flow_tracking`, `vio_triangulation`, `vio_optimisation`, `gravity_scale`, `delayed_marginalisation`, `stationary_detection`, `mapping_detection`, `mapping_matching`, `mapping_triangulation`, `mapping_optimisation`, `timing`, `raw_logs`, `cross_run`), plus two top level settings, `time_reference` and `liftoff_threshold_m`. Each tab holds one key per plot or metric group, always with an `enabled` boolean and, where the quantity needs one, its own hyperparameters.

- `trajectory.alignment_mode`: `"sim3"` (monocular VO, scale unobservable), `"se3"` (stereo VO, scale metric, no gravity reference) or `"posyaw"` (gravity aligned VIO, only translation and yaw unobservable). Not auto detected, an explicit per invocation choice.
- `trajectory.rpe_rmse.deltas` / `trajectory.rpe_length.length`: lists of frame counts the RPE sweep evaluates at.
- `trajectory.trajectory_3d_gt_overlay`: the combined ground truth (every experiment's own ground truth, offset to a common start time and unioned, since all experiments are assumed to replay the same dataset) overlaid in green against each experiment's own aligned estimate.
- `trajectory.drift_proxies`: `closure_error_m`, `scale_drift`, `rotation_drift_deg`, `translation_drift_m`, robot agnostic, no reference altitude or GPS fix required, scalar only, no plot.
- `vio_optimisation.excitation_covariance.window_s`: window length for the windowed specific force covariance.
- `vio_optimisation.stationarity`: the zero velocity stationarity test's own latched flag over time, its two threshold inputs (specific force deviation from gravity, gyroscope norm), and the fraction of frames it latched on, scalar only.
- `stationary_detection`: the three stage stationary body detector's own test statistics (`metrics`, windowed SHOE statistic `t_shoe`, Mahalanobis distance squared `d2`, optical flow magnitude), each stage's own binary pass/fail flag plus the combined `mpIsStationary` flag over time (`stage_flags`), and VISLAM's estimated vehicle speed `v_norm` (`vehicle_speed`), to cross check whether the vehicle was genuinely moving whenever a stage disagrees with the others.
- `mapping_matching.bow_pr_curve.distance_thresh_m` / `.min_time_gap_s`: the ground truth true-match rule for the BoW precision/recall curve.
- `timing.tail_latency_percentiles.percentiles`: percentiles reported for every named timing column across every timing block in the tab, front end, VIO, VIO solver, VIO marginalisation, mapper cycle, mapper detection and mapper matching alike, not a hand picked subset.
- `cross_run.config_diff.baseline`: `"first"` (chronologically first experiment) or an explicit experiment id.
- `cross_run.distribution_comparison.metrics`: which named distributions get a cross run box/violin plot.
- `time_reference`: `"mission"` (default) offsets every experiment's `t_ns` by its first logged row, `"liftoff"` by its own lift off, the first `gt_eval.csv` row whose true height leaves its first value by `liftoff_threshold_m` (default 0.15 m). Use `"liftoff"` in a copy of this file to compare take offs, which happen 3 s to 7 s into each run. An experiment without ground truth or without a lift off keeps the mission reference.
- `gravity_scale`: the VIO estimator's gravity and scale period. Every column of `vio_gravity_scale.csv` (`block_step` on update frames only, `block_cumulative`, `swap_events`, `visual_prior_admission`), the physical errors against ground truth (`physical_scale_gravity`, a scale ratio over `window_s` where the true displacement exceeds `min_disp_m`, the body frame tilt error, the yaw error and a speed ratio where the true speed exceeds `min_speed_mps`), the bias components with the tilt equivalent of the horizontal accelerometer bias (`bias_components`), the per frame position jump not explained by velocity with update frames marked (`position_jump`), the mapper pose update gate (`pose_update_gate`) and solver convergence (`solver_health`). `scalars` writes per run summaries relative to lift off, the median scale ratio over `median_ratio_window_s` and the tilt error at `tilt_at_s`. Update frames are those with a nonzero `sigma_step` or a `tilt_step_deg` above $10^{-3}$, since held frames log about $10^{-6}$ degrees of rounding.
- `delayed_marginalisation`: the delayed store of the gravity and scale period, from `vio_delayed_marg.csv` (`plans/delayed_marginalisation.md`). `events` marks when each readvance and coarse job started, when its prior was installed or the coarse job discarded, and when the delayed phase begins. `job_timing` draws each job's duration in the worker against the frame period before it, the VIO thread's wait for it, its installation and catch up cost and the steps readvanced at installation, `install_lag` the marginalisations between a job's start and its installation, and `store_timing` the store's own cost per marginalisation. `trigger` draws the block's offset from the anchor of the prior in use against the readvance thresholds of each run's `config.json`, `store` the store's size and phase, `coarse_jobs` every logged result of each coarse optimisation, `smoothing` the largest position increment of each smoothed readvance, `scale_at_events` the cumulative scale with every installation marked, and `job_duration_histogram` the distribution of job durations. `scalars` writes event counts, the start of the delayed phase, job duration percentiles, jobs longer than their frame period, the largest wait and installation lag, and the store's cost and size. Both the schema before Change 16 of that plan (`coarse_triples`) and the one after (`coarse_spans`, `wait`, `coarse_timed_out`) are read.
- `raw_logs`: one stacked figure per CSV found in any experiment, every non constant numeric column against `t_ns`, so a newly logged table appears without code. Columns constant within every run are written to the scalars tab as `<csv>.<column>` instead. `exclude` lists CSV base names to skip, and `max_points_per_run` thins each run by a stride.
- `"width"`/`"height"`: set on every plot's own entry, read by `class Analysis._wh` and passed straight to the matching `visualisation.py` call. Sized assuming a 1440px wide MacBook viewport, a single axis plot at 1080px (three quarters of the screen) or 720px (half) depending on whether its x axis needs the room, a multi subplot figure at 1080px wide and tall enough for every one of its rows, a 3D trajectory plot at 1080x810. Left off only where the entry has no plot of its own, scalar only quantities.

Every scalar computed anywhere in `class Analysis`, not only the ones a plot also draws, is written to `metrics.csv` and the `scalars` tab, never as a tile shaped figure of its own, as `(category, name, type, value)`. A quantity naming several related sub quantities, VIO's cost split by term or the marginalisation nullspace response's seven named directions among them, is one figure with one subplot per sub quantity and one trace per experiment within it, `visualisation.multi_axis_time_series`/`multi_axis_histogram`, so experiments compare directly within an axis and every subplot's zoom and pan is linked within that figure, and, since it is also `t_ns` based, across every other linked figure on the page too.
